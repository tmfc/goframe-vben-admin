# Specification: System Dictionary Management (Full-stack Enhancement)

## 1. Overview
本 Track 旨在为系统字典管理提供完整的全栈解决方案。除在 `web-naive` 中实现管理界面外，还包括后端导入导出接口的开发，以及针对多语言配置和状态切换的逻辑增强。

## 2. Functional Requirements

### 2.1 前端：界面布局与交互 (web-naive)
- **字典类型管理**：主页面展示字典类型列表，支持按类型编码和名称搜索。
- **字典数据管理**：点击类型后，在右侧 Drawer/侧边栏管理该类型下的字典数据。
- **多语言编辑 (i18n)**：
    - 表单默认展示中文输入。
    - 支持动态添加语种（下拉选择语种 + 输入文字）。
    - 逻辑：根据该字典类型已有的语言配置（从后端获取）自动带出待填写的输入项。
- **状态切换**：列表页提供 Switch 开关，一键启用/禁用。
- **导入导出 UI**：提供上传文件（导入）和点击下载（导出）的交互。

### 2.2 后端：接口与逻辑增强 (GoFrame)
- **导入/导出 API**：
    - 实现字典类型与数据的导出接口（支持导出为 Excel/JSON 格式）。
    - 实现字典导入接口，需处理数据覆盖、重复校验及关联关系。
- **状态变更接口**：确保提供原子化的状态更新接口，供前端 Switch 调用。
- **多语言字段支持**：优化 `label_i18n` (JSONB) 的处理逻辑，确保导入导出时多语言数据不丢失。
- **权限与审计**：为新接口配置 Casbin 权限，并确保导入操作记录审计日志。

## 3. Non-Functional Requirements
- **事务处理**：导入操作必须支持事务，确保部分失败时整体回滚。
- **自动缓存处理**：后端在任何字典数据变更（增删改、导入、状态切换）后必须自动失效/更新 Redis 缓存。
- **权限控制**：根据角色动态控制按钮可见性（前端）与接口访问（后端）。

## 4. Acceptance Criteria
- [ ] 用户可在 `web-naive` 菜单进入字典管理页。
- [ ] 能够成功创建字典类型，并在右侧面板管理其数据。
- [ ] 字典数据多语言标签正确保存并能回显。
- [ ] 状态开关点击后立即生效且刷新后状态一致。
- [ ] **后端验证**：通过接口或 UI 导出数据，修改后重新导入，数据一致且关联正确。
- [ ] 无相应权限的用户无法通过 UI 或直接调用 API 执行敏感操作。

## 5. Out of Scope
- 其他业务模块对字典数据的消费逻辑。
